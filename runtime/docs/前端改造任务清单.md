## 0. 为什么要做这一轮

界面本身功能是齐的（24 项需求都实现过），问题是**信息架构**，不是功能缺失。实际使用中反复出现的四件事：

| # | 现象 | 根因 |
|---|---|---|
| 1 | 想改个存图天数，在"配置"页里翻了半天 | 一个页签塞了 10 个板块、50 多个输入框，没有分组 |
| 2 | 现场问"为什么不出包"，要在 4 个页签之间来回跳着看 | 宿主 / 通道 / 相机 / 下游 / 磁盘 分散在不同页 |
| 3 | 客户看不懂"应用 A8-3 模板""B8 监控" | 标题里带着需求编号 |
| 4 | 报错弹窗挡住整个界面，扫包时一直弹 | 早期用 `window.alert`（已改成右下角 toast，仍有残留文案） |

**这一轮就是把 1 和 2 解决掉，顺带把 3 和 4 收口。**

---

## 1. 三条不能破的线

这三条是本清单的"红线"，任何一个任务包违反就算不合格：

1. **元素 id 一个都不能改。** 19 个回归脚本靠 `id="…"` 断言（`tab-*`、`hostState`、`camEditRows`、`btnApply`、`auth*`…）。要改名必须同步改回归脚本，那就不属于"只动前端"了。
2. **不新增后端接口，不改接口字段。** 前端只能重组现有接口的调用方式。代价是某些功能要用"组合现有接口"实现（例如 T6 的前端版一键自检）。
3. **改完必须跑 `node build.mjs`。** 它会把 `js\*.js` + `app.css` 的内容算成指纹写进 `index.html`（`?v=xxxxxxxx`），不跑的话现场浏览器会拿缓存，改了看不到效果。

### T1 页头状态条（✅ 已完成，V1.0.9 热修）

**做了什么**

页头常驻 5 个状态胶囊 + 1 个实时通道，5 秒刷一次。这六件事任意一个不满足都"出不了包"，所以放在最显眼的位置：

| 胶囊 | 数据来源 | 判定 |
|---|---|---|
| 采集宿主 | `GET /api/host/status` | running→绿；retrying→黄（显示第几次重试）；其它→红 |
| 命令通道 | `GET /api/host/channel` | 可用→绿；宿主在跑但通道断→红；宿主没跑→黄（不跟着再报一次红） |
| 相机 | `GET /api/devices` | 全部在线→绿；部分在线→黄；全掉→红；清单为空→灰 |
| 下游 | `GET /api/downstream` | 未启用→灰；TCP 已连接 / HTTP 推送 / 服务端有人连→绿；未连或失败→黄 |
| 图片盘 | `GET /api/stats` | <70%→绿；≥70%→黄；≥85%→红（附"超过 85% 会造成丢图"） |
| 实时通道 | SSE `onStatus` | 连上→绿；重连中→红 |

**轮询的三条规矩（很重要，别改回去）**

1. **没登录就不发请求。** 用 `auth.ts` 新导出的 `canRead()` 判断（已登录 / 没开鉴权 / 只读接口没受保护，三种才算"能读"）。不在这个门后面拦住的话，后台轮询拿到 401 → `onUnauthorized` → 弹登录框 → **把用户正在输密码的光标抢回用户名框**（这是历史上真实踩过的坑）。
2. **下游状态单独走一个"安静版"入口** `api.downstreamQuiet()`。`/api/downstream` 是受保护接口（同路由有 POST），未登录会 401；`downstreamQuiet` 打同一个接口但 `silent401`，只有它用于状态条。输出对接页仍然用原来的 `api.downstream()`。
3. **单个接口失败只染它自己那一个胶囊**，不会把整条状态条拖红；文字没变就不写 DOM。

**验收（已实测）**

| 项 | 实测值 |
|---|---|
| 宿主 / 通道 / 相机 / 磁盘胶囊取到真值 | `采集宿主：运行中`(绿)、`命令通道：可用`(绿)、`相机：1/1 在线`(绿)、`图片盘：92%`(红) |
| 未登录时下游胶囊 | `下游：登录后显示`（灰），且**没有弹登录框** |
| 页面加载时不再出现"登录已过期"误报 | ✅（状态条不再产生 401） |

**2026-09-24 补丁：「相机」胶囊的口径（A+B）**

换完二进制当天发现了这个假阳性，现场实证：宿主在报 `SDK 返回 3000（发现不到相机）`，
而"相机"胶囊亮着绿灯 `相机：1/1 在线`。根因是两格取数来源不同 ——
宿主格读 `logs\host-status.json`（实时），相机格读 `/api/devices`（**平台收到的上一次相机状态快照**）；
宿主连不上相机时不会再发"离线"事件，平台只能沿用旧结论。

改法（只动 `statusbar.ts`）：

| 情形 | 现在显示 |
|---|---|
| 宿主 `retrying` + SDK 返回 3000 / 3001 / 2200 | **红**：`相机：SDK 发现不到` / `相机被占用` / `没有加密狗`（悬停给出完整原因 + 宿主 note） |
| 宿主 `retrying`，返回码认不出 | 黄：`相机：待确认` |
| 宿主没在跑，且宿主状态文件 > 90 秒没刷新 | 灰：`相机：状态过期`（说明清单是上次会话留下的） |
| 宿主没在跑 | 灰：`相机：宿主没在跑` |
| 宿主在跑 | 才按 `/api/devices` 报在线数（绿 / 黄 / 红） |

悬停提示统一补一行 `清单 N 台（在线 x，离线 y）` 和 `最近一次相机数据：N 分钟前`
——最后这条**只作参考不做判据**：空闲线体上心跳本来就会一直变大，用它判故障会把正常线体误报成过期。

实测（现场 8090，宿主正报 3000）：胶囊由绿转 **红 `相机：SDK 发现不到`**，悬停为
`SDK 返回 3000：没有相机连上（相机没上电 / 网段不对 / 上次会话没释放）。… 清单 1 台（在线 1，离线 0）最近一次相机数据：44 分钟前`。
结构体检 11/11、C1 32/32、包核验 7/7。

**2026-09-24 补丁二：KPI 与相机状态墙也对齐同一口径**

同一个假阳性在实时页还有两处：KPI「相机在线 / 总数」（取 `/api/stats` 的 camerasOnline）和
"相机状态墙"（取相机事件快照）。两处都跟着显示"在线"，和页头胶囊自相矛盾。

改法：把判定抽成**一份共享结论**（`statusbar.ts` 顶部的 `HostVerdict`，
`verdictFromHost()` 是纯函数、`setHostVerdict()` 发布、`onHostVerdict()` 订阅），三处都用它：

| 位置 | 数据不可信时显示 |
|---|---|
| 页头「相机」胶囊 | `相机：SDK 发现不到`（红）/ `相机被占用` / `没有加密狗` / `待确认` / `状态过期` / `宿主没在跑` |
| 实时页 KPI | 不再报 `1 / 1`，直接显示同一个结论词，卡片按结论染色（`.card bad/warn/unknown`） |
| 相机状态墙 | 每格的在线字样换成结论词、左下色条转红/黄；汇总行写 `相机状态：SDK 发现不到（下面各格是上一次会话的在线状态）` |
| 相机表格视图 | 状态列同样换成结论词（墙和表格不能两种说法） |

实测（现场 8090，宿主仍在报 3000）：三处同时为 **`SDK 发现不到`**，
KPI 卡片 class=`card bad`，墙格 `camcell offline alarm`，汇总行带"上一次会话"的说明；

### T2 实时监控页打磨（2 天）

**要解决的问题**：实时页现在 KPI 只有 4 个、告警挤在一条灰条里、卡片和相机墙的徽标样式各写各的。

**做这些**

5. **相机状态墙**：每张卡左边加 3px 状态色条（绿 / 黄 / 红），一眼扫出异常；卡内第一行 `相机名 + 方位` 与右侧状态词（在线 / 心跳慢 / 离线 / 未发现），第二行 `出码 N · 在线率 N%`。从没触发过的相机显示"出码 0 · 未触发"，**别显示 0%**（会被当成故障）。

7. 卡片墙空态："还没有包裹 · 点「软触发一次」试一下"。

### T8 过包区改版：大图 + 限高滚动列表 + 解码绿框（✅ 已完成，2026-09-23）

**背景（用户原话的意思）**：最新过包那块不要"卡片/表格切换"，要**图片和列表分开**——
上面一个固定视图框只显示当前包裹读到的图（读到码显示带绿框的图，无码显示拍到的原图），
下面一个限高、自带滚动条的列表框。

**做了什么**

1. **布局**：取消"卡片 / 表格"二选一，改成上面一张固定大图、下面限高可滚动的列表
   （`.plistwrap` 限高 236px、自己的滚动条；表头与行用同一套六列网格对齐）。
2. **大图**：只显示**当前包裹**那一张原图。读到码 → 叠绿框 + 单号；无码 → 照样显示拍到的原图，只是没有框；
   没图的包 → 明确写"这一包没有图片（只上报了条码）"。
3. **绿框从哪来（关键结论）**：**不是相机给的第二张图**，是大华 SDK 给条码点坐标、客户端自己画。
   证据：Demo 里 `BaseCodeData.AreaList` 的注释写着"用于将图片中的条码用画框圈出来"；
   `ImageView` 把 `AreaList` 当叠加层画在原图上；`ImageHelper` 里还有一段"把框和单号烧进 jpg"的现成代码。
4. **实现路线**（选"前端叠框"，没选"宿主烧图"）：

   | 层 | 做了什么 |
   |---|---|
   | 大华插件 | 读 `e.AreaList`（一个条码 5 个点），按图片宽高**归一化 0~1**，挂在图片上（`ImageRef.Boxes`）；第一次拿到时打一条 `[greenbox]` 日志 |
   | 核心模型 | 新增 `ImageBox` / `ImageBoxPoint`，`ImageRef.Boxes` |
   | 仿真插件 | 造一个固定位置的假框 —— 没相机也能把整条链路和界面跑通 |
   | 宿主 | 写进 spool：`"boxes":[{"code":"...","points":[[x,y],…]}]` |
   | 平台 | 透传到 `/api/parcels` 的 `imageBoxes`（跟 `firstImagePath` 那张图走） |
   | 前端 | `parcelview.ts`：归一化坐标 → SVG 折线（`viewBox 0 0 1 1` + `non-scaling-stroke`）+ 单号标签 |

   选前端叠框的理由：图文件不变、磁盘不涨（现场已经 92%）、BMP/JPG 都能叠、无码天然无框；
   以后要给下游"带框 jpg"，按同一份坐标加个开关就行。
5. **交互**：默认跟随最新；点列表某一行或往下滚 → 暂停跟随并出现「回到最新」；点它回到最新并滚回顶部。

**这条越过了"只动前端"的边界**：坐标只有碰 SDK 的那一侧（宿主）能拿到，
所以 `DwsEdge.Core` / 大华插件 / 仿真插件 / 宿主 / 平台都改了 —— 这是本清单里第一条跨前后端的任务。

**验收（已实测，仿真链路）**

## 附录 B：与设计图的有意差异（登记）

这些地方和设计图不一样，是**故意**的，不是漏项。写下来免得下次有人"顺手改回去"。

| 项 | 设计图 | 我们的决定 | 理由 |
|---|---|---|---|
| 默认主题 | 跟随系统（设计图默认 `auto`） | **默认深色** | 现场大屏一直是深色。默认跟随系统的话，Windows 是浅色模式的机器一升级整个界面就变白 —— 那是惊吓不是升级 |
| 状态胶囊数量 | 4 个（宿主 / 相机 / 下游 / 图片盘） | **6 个**（多"命令通道""实时通道"） | 命令通道决定软触发、补码能不能用；实时通道决定界面上的数据是不是活的。都属于"一票否决"，不该藏起来 |
| 主题 / 密度 / 导航形态的入口 | 在设计图自己的下拉调试面板里 | 放进页头"显示设置" | 设计图那个面板是画图工具的调试件，不是产品界面；这三项现场要能自己改 |
| 主按钮颜色 | 实心绿（`#2ea043` / `#1f883d`） | 沿用现有蓝色主色 | 不动已交付的观感，避免"升级完像换了个软件" |
| 信息密度数值 | 字号 14→12.5px、行高 34→27px | 字号 **13→12px** | 与现有界面字号基线对齐，不引入新字号档位 |
| 品牌名 | "莱茨酷氪 DWS 物流解码平台 · V1.0.9 · 六面扫" | 去掉"· 六面扫" | 产品要扩狂扫 / 快手，把场景名写进品牌区会自相矛盾；场景信息属于项目配置，不属于产品名 |
| 过包区形态 | 卡片墙（缩略图 + 标签） | **上面大图 + 下面限高滚动列表**（T8） | 用户明确要求"图片和列表分开、不要切换"；卡片那张缩略图看不清面单，也看不清解码框 |
