# 包裹异常检测（叠件 / 异形 / 尺寸 / 类型）可行性评估

> 结论先行版。评估对象：大华 DWS SDK 的 AI 模块字段，**先不动代码**。
> 证据来源：大华官方 C# Demo 源码（`DWS_Demo_C#_Win64_V3.8.006`）+ 我们 SDK 目录里
> `LogisticsBaseCSharp.dll` 的元数据。每条结论都可以照着复查。

---

## 1. 一句话结论

**大华这套 SDK 自带"AI 异常件检测"，字段是现成的，不用我们自己训模型。**
但它**不含"破损"** —— 枚举里没有破损 / 破洞 / 受潮这类取值，最接近的是"异形件 / 尺寸异常 / 翘边"。
所以：

* 想做**异常件（叠件、异形、小间距、尺寸异常、回流、集包袋、纸箱、泡沫箱、软包）**：现在就能做，属于"把已有字段接出来"。
* 想做**包裹破损**：SDK 不给，要么拿它的 AI 图自己训模型，要么另配相机/算法。**别对客户直接承诺"破损检测"**。

---

## 2. 能拿到哪些字段

回调（`OutputResult == 1`，也就是"条码 + 重量 + 体积"那一次）里带 `AIData`：

| 字段 | 含义 | 取值 |
|---|---|---|
| `PackageAbnormalStatus` | AI 包裹叠件状态 | `0` 正常 / `1` 叠件 / `2` 异形件 |
| `PackageAbnormalType` | 包裹类型（枚举 `AbPackDetPackageType`） | 未知类型 / 叠件 / 异形件 / 小间距 / 尺寸异常 / 正常件回流 / 集包袋 / 纸箱 / 泡沫箱 / 软包 / 其他类型 |
| `AiBPJInfo.rect` | **包裹位置框**（点多边形，跟条码框同一个套路） | 一组点坐标 |
| `AiBPJInfo.packageNum` | 这一帧里有几个包裹 | 整数（>1 就是叠件/连包） |
| `AiBPJInfo.packageWarpe` | 是否翘边 | `0` 无翘边 / `1` 翘边 |
| `AIImage` | AI 彩色图 | 一张图（跟原图一样可以落盘） |
| `AIDepthImage` | AI 深度图 | 一张图 |
| `AiVolumeInfo` | AI 算出的体积 | 长/宽/高（毫米）+ 体积（立方毫米） |

## 3. 证据（可复查，不用信我）

1. **字段定义**：Demo 的 `CodeData.cs` 里 `AIData` / `BPJInfo` 两个结构 ——
   `PackageAbnormalStatus`、`PackageAbnormalType`、`rect`、`packageNum`、`packageWarpe`、`AIImage`、`AIDepthImage`、`AiVolumeInfo` 全在里面。
2. **取值含义**：Demo 的 `Form1DWS.cs` 里有两张字典 `bagStatusTypeDict` 与 `AbPackDetPackageTypeDict`，
   就是上面第 2 节那张表 —— 大华自己把枚举翻译成了中文。
3. **SDK 里确实有这些名字**：在 `runtime\LogisticsBaseCSharp.dll` 的元数据里逐个查到
   `PackageAbnormalStatus`、`BPJInfo`、`AbPackDetPackageType`（说明这些不是 Demo 自己编的）。
4. **调用点**：Demo 在 `OutputResult == 1` 的分支里读这些字段，并用 `AIBPJInfo.rect` 在图上画包裹框 ——
   跟我们在做的"条码绿框"是同一套做法（**框都是客户端拿坐标画的**）。

## 4. 落到我们系统要改什么

这条链路和我们刚做完的"解码绿框"**完全同源**（宿主取字段 → spool → 平台 → 前端叠框），
所以复用的部分很多，属于"顺着已有管道再接一路数据"：

| 层 | 改动 | 说明 |
|---|---|---|
| 宿主（大华插件） | 解析 `AIData`，把异常状态/类型/翘边/包裹数/包裹框写进事件 | 绿框那套 `ImageBox` 可以直接复用给 `rect` |
| 核心模型 | 事件里加 `Abnormal` 小结构 | 厂商无关，别的厂商没有就留空 |
| 平台 | 透传到 `/api/parcels`、历史库、统计维度 | 历史页按"异常类型"筛，统计页出"异常件占比" |
| 前端 | 实时页/历史页给异常包打标（红标 + 类型），大图上叠包裹位置框 | 和绿框同一层 SVG |
| 下游 | 按异常类型打标下发（WCS 分流 / 人工复核口） | 模板加占位符即可 |

粗估：**宿主 + 模型 0.5 天，平台透传与历史 0.5 天，前端展示 1 天**（不含现场联调）。

## 5. 前提与要跟大华确认的事（这几条不确认，做出来就是空的）

1. **哪些相机型号支持**：现在现场的 `DH-MV-RH7B00MG200`（Huaray）支不支持 AI 异常检测？
   要不要换成带 AI 的型号。
2. **有没有额外授权**：AI 模块是否要单独的加密狗项 / License（我们有 2200 加密狗报错的先例）。
3. **SDK 配置开关**：`Cfg\LogisticsBase.cfg` 里现在看不到 AI 相关段，要问清楚是哪个配置项开关。
4. **标定与算力**：深度图 / AI 体积是否需要单独标定；开了 AI 之后对读码时延、CPU 占用的影响。
5. **字段可靠性**：`packageWarpe`（翘边）在现场光照/包裹颜色下的误报率，最好让他们给一段实测数据。

## 6. 为什么值得做（商业上）

* **同行没有**：多数集成商只交付"读码 + 称重 + 体积"，异常件回看与报表是空白；
  而这套数据**不用加硬件**，我们已经有宿主和平台。
* **价格锚点不一样**：DWS 本身卖不上价，但"异常件复核 + 出问题能回看证据"是甲方愿意单独付钱的能力。
* **和现有能力叠加**：异常包自动关联它的六面图 + 条码，形成"证据链"，这正是分拨中心扯皮时最需要的东西。
* **顺便靠近破损**：先用现成的"异形件 / 尺寸异常 / 翘边"把流程和界面跑通，
  以后要上真正的破损模型，接的是同一个位置、同一张 AI 图。

---

## 7. 风险与不要做的事

* **不要把"异常件"宣传成"破损检测"** —— 枚举里没有破损，说了就是给自己挖坑。
* 不要把 AI 图当主图存：AI RGB + 深度图会让磁盘占用翻倍（现场磁盘本来就紧张），
  建议只存"异常包"的 AI 图（正常包不留），并把保留天数调短。
* AI 字段只在 `OutputResult == 1` 才有，所以**"先条码后重量体积"两次回调的合并逻辑不能动**，
  异常信息要挂在合并后的那条记录上。
