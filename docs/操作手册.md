# DWS 物流解码平台 · 现场操作手册

> 适用版本：V1（方案 B：采集宿主 + 业务平台）
> 适用对象：现场调试 / 交付 / 运维人员
> 配套文档：`README.md`（架构与实现细节）、本手册（怎么操作）

本手册只讲"怎么操作"，按现场顺序编排：**准备 → 部署 → 配置 → 日常 → 现场动作 → 故障 → 验收**。
每条命令都给出"预期结果"，出错时能立刻知道卡在哪一步。

---

## 0. 五分钟跑通（没有相机也能验）

新盒子到手、或交付前想先确认软件没问题，用**仿真模式**跑一遍（不需要相机和加密狗）：

```powershell
cd <交付包目录>                       # 里面有 DwsEdge.Host.exe 与 runtime\ 的上一层

# 1) 把采集宿主切到仿真 provider（改 config\gateway.ini 里 [runtime] 的 provider）
notepad runtime\config\gateway.ini    # provider=simulator

# 2) 同时起平台 + 采集宿主，并自动触发一次过包
.\run.ps1 -Both -TriggerOnce

# 3) 浏览器打开平台的诊断页与实时页
start http://localhost:8090
```

预期：采集宿主控制台出现 `[parcel] 条码 ... 相机=simulator-cam ...`，平台实时页出现一张包裹卡片。
看完把 `provider` 改回 `dahua-dws`（真机模式）。

> `-Both` 会让采集宿主在前台、平台在后台**同时常驻**，按 Ctrl+C 会一起停掉；
> 只想快速验一下就加 `-Duration 10`（10 秒后宿主自动退出，平台也随之停止）。

> 仿真模式用来验"软件链路"，**不代表相机/加密狗/光电已经验过**。真机验收见第 8 章。

## 1. 装机前的准备

### 1.1 硬件与网络

| 项目 | 要求 |
|---|---|
| 上位机盒子 | Win10/11 x64，**无风扇**机型可用；建议 4 核 / 8G 起，系统盘 SSD，**图片盘单独一块**（见 3.3） |
| 网口 | 建议两块：一块接相机网段，一块接现场/管理网 |
| 相机网段 | 相机与盒子同网段，互 ping 通；不要跨越路由器/交换机做 NAT |
| 加密狗 | 大华 USB 加密狗必须插在**盒子本机**（不能通过网络共享） |
| 光电/编码器 | 接相机 IO 或经相机触发（硬触发模式依赖它） |
| 磁盘 | 图片按天保留，先算好容量：17 台相机 × 每包 N 张 × 每天包量 × 保留天数 |

### 1.2 网络与端口规划（建议写进交付记录）

| 用途 | 默认值 | 说明 |
|---|---|---|
| 平台网页/API | **8090**（TCP，入站） | 浏览器访问 `http://<盒子IP>:8090` |
| 下游对接（平台做客户端） | 由现场指定 | 出站，连下游的地址端口 |
| 下游对接（平台做服务端） | 由现场指定 | 入站，下游连盒子 |
| 相机 | 相机网段 | 采集宿主与 SDK 使用 |

放行 8090 入站（管理员 PowerShell）：

```powershell
netsh advfirewall firewall add rule name="DWS-Platform-8090" dir=in action=allow protocol=TCP localport=8090
```

### 1.3 交付包内容

```
<交付包>/
├─ run.ps1                  启动脚本（采集宿主 / 平台）
├─ build.ps1                编译脚本（现场一般不用）
├─ runtime/                 ← 实际运行的东西都在这里
│  ├─ DwsEdge.Host.exe      采集宿主（net48，Win 自带运行时）
│  ├─ providers/            相机插件（大华 / 仿真）
│  ├─ platform/             业务平台（net10.0，**需要 .NET 10 运行时**）
│  ├─ Cfg/                  SDK 配置（相机清单、触发模式）
│  ├─ config/               本软件配置（gateway.ini / 平台各配置 json）
│  ├─ images/  spool/  logs/  data/   图片 / 事件 / 日志 / 历史库
│  └─ tools/                运维脚本（自检、一键应用、命令通道…）
└─ docs/
   └─ 操作手册.md           本文件
```

> **.NET 10 运行时**：平台是 net10.0 程序。如果目标机器没装，请把
> `dotnet-runtime`（或 ASP.NET Core Runtime 10）安装包一起带上，装完再启动平台。
> 采集宿主是 .NET Framework 4.8，Win10/11 自带，不用装。

## 2. 首次部署（按顺序做）

### 步骤 1：拷贝交付包

整个目录拷到盒子，例如 `D:\dws\`。**不要**只拷 exe 的几个文件——`runtime\` 里的 SDK DLL、Cfg、tools 都要在。

### 步骤 2：确认相机清单与触发模式

打开 `runtime\Cfg\LogisticsBase.cfg`（GB2312 编码，用记事本另存时**不要改成 UTF-8**），确认这三处：

```
<ImageAcq mode="2" num="17" ... />                                  ← num = 相机台数
<ReadCodeMode triggerMode="1" ... />                                ← 1=硬触发（光电） 2=软触发 0=自由拉流
<Camera ip="172.20.10.11" enable="1" />                             ← 每台相机一行，enable="1"
```

三种改法（任选）：

| 方式 | 命令/位置 | 适用 |
|---|---|---|
| 界面（推荐） | 平台 → 配置 → 相机清单表格 → 保存并应用 | 有网络、能开浏览器 |
| 清单文件 | `powershell -ExecutionPolicy Bypass -File .\tools\apply-config.ps1 -CameraList .\config\cameras-17.example.txt` | 批量、17 台一次配好 |
| 只改触发模式 | `powershell -ExecutionPolicy Bypass -File .\tools\set-trigger-mode.ps1 -Mode hard` | 现场只想切触发方式 |

> `apply-config.ps1` 的流程是"写配置 → 启动 SDK 回读校验 → 不通过自动回滚"，
> 所以它会**占用相机**（会先停采集宿主）。退出码：0 成功、1 参数错、2 校验失败已回滚、3 其他异常。

### 步骤 3：启动采集宿主

```powershell
cd D:\dws
.\run.ps1
```

预期（真机）：滚动出现 `provider 能力 = ...`、`相机 xxx 上线`、`已上报相机快照 N 台`。
如果报错，看 `runtime\logs\host-<日期>.log`，并对照第 6 章故障表（2200 = 加密狗、3000 = 相机数与清单不符）。

### 步骤 4：启动业务平台

另开一个窗口（或让平台常驻另一个会话）：

```powershell
cd D:\dws
.\run.ps1 -Platform
```

预期：`Now listening on: http://0.0.0.0:8090`。

> 两个进程都要常驻。当前版本是控制台进程，重启机器后需要人工拉起（服务化在下一步计划里）。

### 步骤 5：首次登录并改密

0. **先确认用哪个地址访问**（平台监听 `0.0.0.0:8090`，即本机所有网卡）：

   | 谁在访问 | 用什么地址 | 说明 |
   |---|---|---|
   | **盒子本机上**的浏览器 | `http://localhost:8090` 或 `http://127.0.0.1:8090` | 最稳；`localhost` 若被解析成 IPv6 回环可能打不开，那就用 `127.0.0.1` |
   | **同网络其它电脑/手机** | `http://<盒子局域网IP>:8090` | 例如 `http://10.176.165.43:8090`；盒子 IP 用 `ipconfig` 看"IPv4 地址" |

   查盒子 IP：在盒子上执行 `ipconfig`，取与访问方**同网段**的那个 IPv4 地址
   （盒子常有两块网卡：相机网段一块、管理网段一块；给现场看网页用管理网段那个）。

   ```powershell
   ipconfig | Select-String 'IPv4'
   ```

1. 浏览器打开上面确认好的地址
2. 初始管理员账号与密码在 `runtime\config\admin-initial-password.txt`（首次运行自动生成）
3. 登录后：**配置 → 账号与安全 → 修改我的密码**（改完那个初始密码文件会自动删除）
4. 顺手在同一个页面把现场用的账号建好（见 4.6）：调试人员给 `operator`，只看看数据的给 `viewer`

### 步骤 6：跑一次一键自检

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\self-check.ps1
```

预期：输出一张表，最后给"该做什么"。没有失败项才算这一步通过。
接真机时它会真的启动一次 SDK 做校验（最长 3 分钟），并检查软触发、磁盘水位、下游连通。

## 3. 配置（按这个顺序配，后面的依赖前面的）

全部在浏览器里：**配置**页。（命令行做法见第 5 章）

### 3.1 相机清单 + 安装方位

配置页 → **相机清单（表格编辑）**：每行一台，选接入方式（ip / key / id）、填值、选方位。

| 校验规则 | 说明 |
|---|---|
| 值不能为空 | 空行自动忽略 |
| `ip` 必须是合法 IPv4 | 写错网段是"相机连不上"的头号原因；要填主机名请改用 `id`/`key` |
| 不允许重复 | 同一接入方式下值不能重复 |
| 台数提醒 | 不在 12-17 之间会给提醒（不拦） |

改完点 **保存并应用**：写 cfg → 启动 SDK 回读校验 → 失败自动回滚。结果会显示在下方输出框里。

方位也可以在 **设备信息页** 逐个改（下拉选择 + 保存方位），改完需要重启采集宿主生效。

#### 清单可以继续按 IP 写（宿主会自动关联 IP ↔ 序列号）

大华 SDK 的接口**不回报相机 IP**，只给「厂商:序列号」这种标识；而现场按 IP 配清单最省事。
采集宿主会把两者自动关联起来，所以清单照旧写 IP 就行：

| 环节 | 做什么 |
|---|---|
| 启动时 | 读 SDK 日志 `runtime\Log\default.log` 里的 `IP-Key` 配对，立刻建好对照 |
| 运行中 | 用扫码回调里的 `CameraIP` 字段持续校正（SDK 官方字段，最权威） |
| 落盘 | 写到 `runtime\config\camera-identity.ini`，一行一条 `ip=key`，可手改，删掉会自动重建 |

效果：清单写 `ip=100.100.100.11`，设备信息页只有**一条**该相机（在线、方位正确），
不会再出现"一条 IP 声明永远离线 + 一条 SDK 发现的设备未在清单中"。
日志里会有这么一行可以对照：

```
相机身份关联：ip=100.100.100.11 ↔ SDK Key Huaray Technology:BK27440AAK00036（清单按 ip 写，SDK 按 Key 上报）
```

> 例外：如果这台相机**一次包裹都没过**、且 SDK 日志里也没有它的 `IP-Key` 记录，
> 界面会暂时把清单那条显示为离线（declared-missing）；过第一个包裹后会自动补上。

### 3.2 触发模式

| 模式 | triggerMode | 用在哪 |
|---|---|---|
| 硬触发 | 1 | 六面扫：光电触发（现场常用） |
| 软触发 | 2 | 调试、手动触发一次；上位机发指令 |
| 自由拉流 | 0 | 狂扫：相机连续出图 |

改法：配置页 → 一键应用配置 → 触发模式下拉 → 一键应用；或 `set-trigger-mode.ps1 -Mode hard|soft|free`。

### 3.3 存图策略（图片盘与保留）

配置页 → **存图策略**：

| 参数 | 建议 |
|---|---|
| 保存原图 / 面单图 | 一般都开；只要原图时关掉面单图省空间 |
| 保存每台相机各自的图 | 默认关。开了必须同时开"回传每台相机的码信息"，否则拿不到相机标识 |
| 图片保存天数 | 按图片盘容量算（现场常见 7-30 天） |
| 磁盘水位(%) | 到线后从最旧的日期目录开始删；**建议 80-85**，别等盘满了才发现 |
| 图片目录 | 指到**独立数据盘**（如 `D:\dws-images`）：留空=用 provider 段的默认目录 |
| 事件文件保留天数 | spool 保留，平台消费过才会删 |

**改完必须重启采集宿主**（宿主只在启动时读 `gateway.ini`）。

### 3.4 下游对接（把包裹数据发出去）

配置页 → **下游输出**。三种模式选一种：

| 模式 | 平台角色 | 现场用法 |
|---|---|---|
| TCP 客户端 | 平台主动连下游 | 下游是服务端（常见） |
| TCP 服务端 | 平台监听、下游连进来 | 下游是客户端；可勾"接入时补发最近 N 条" |
| HTTP 推送 | 平台 POST 到下游接口 | 下游是 HTTP 接口；带幂等键（默认头 `Idempotency-Key`，值为包裹追踪号） |

要点：

1. **数据格式模板**：默认 `{code}|{time}|{camera}|{weight}|{volume}|{traceId}\r\n`。
   可用的字段点"模板预览"就能看到；`\r\n` 是行结束符（下游按行读时必须有）。
2. **模板里建议带 `{traceId}`**：下游可以按它做去重。
3. 配置完点 **测试连接**，再看"最近下发记录"是否出现成功记录。
4. 下游断线期间包裹会排队（不丢），恢复后自动补发；失败按重试间隔一直重试。

### 3.5 条码过滤规则（可选）

配置页 → **条码过滤规则**：按优先级从小到大判断，**第一条命中的规则决定结果**。
支持长度 / 前缀 / 后缀 / 正则 / 白名单 / 黑名单；保存后**立即生效**（热加载）。

配完用"规则测试"贴几条真实条码验证，再看"最近被丢弃的条码"确认现场效果。

### 3.6 相机监控与告警阈值

配置页 → **监控与告警阈值**：心跳超时、离线告警秒数、频繁掉线次数、在线率下限等。
默认值（心跳 60s / 离线 10s / 检查 5s）适合大多数现场；网络抖动多的场地可以把"离线告警"调大到 20-30 秒，避免告警刷屏。

### 3.7 班次设置（统计用）

统计页 → **班次设置**：默认白班 08:00-20:00、夜班 20:00-08:00。
跨天班次（如 22:00-06:00）的凌晨时段算**前一天**那一班，符合现场口径。

### 3.8 配置模板（批量交付用）

配好一台设备后：配置页 → **配置模板** → 填名称（如 `6面扫-17台`）→ **把当前配置另存为模板**。
模板文件在 `runtime\config\templates\`，拷到另一台设备的同目录 → 那台点 **对比**（先看差异）→ **套用**。

模板只含**采集侧**三件套：相机清单（含方位）+ 触发模式 + 存图策略。平台侧（下游/规则/阈值/班次）不被动。

### 3.9 备份与回滚

每次保存配置都会自动生成 `*.bak-时间戳` 备份（`config\` 与 `Cfg\` 下）。
配置页 → **配置备份与回滚**：选一份点"回滚"即可还原；**回滚前会把当前内容再另存一份**（`.before-rollback-*`），不怕点错。

回滚后的生效方式页面会写明：平台配置是热加载、采集宿主配置要重启宿主、SDK 配置要重新"一键应用"。

## 4. 日常操作（界面每一页干什么）

### 4.1 实时监控页

| 区域 | 看什么 |
|---|---|
| 顶部 KPI | 包裹总数 / 读码率 / 无码数 / 相机在线数 |
| **告警条** | 正常是绿色；有相机告警变黄/红，点一下跳到设备信息页看记录 |
| **最新过包卡片墙** | 一张卡=一个包裹：缩略图（点击看原图）、条码+方位、时间、相机、状态徽标（读码/NOREAD/更新×N/图N/已下发/下发失败） |
| **相机状态墙** | 每台相机一格：在线状态、**出码计数**、掉线次数、心跳、在线率、告警徽标；绿=正常 红=离线 黄=清单未发现 |

两个区域右上角都能在"卡片 / 表格"之间切换，选择会被浏览器记住。

**「软触发一次」按钮**：在"最新过包"标题右边。点一下给正在跑的采集宿主发一次软触发
（走常驻命令通道，不用停宿主），结果直接显示在按钮下方：
成功显示"已触发（退出码 0）"；宿主没跑显示"命令通道连不上"；退出码 5 说明当前不是软触发模式。

### 4.2 设备信息页

- 相机清单与设备信息（型号/序列号/厂商/固件/掉线次数/出码数）
- 安装方位编辑（六面扫：顶/底/左/右/前/后）与六面概览
- 相机状态监控与告警（在线率 / 心跳 / 出码 / 当前状态持续 / 活动告警 + 掉线记录表）
- 导出 CSV（设备清单）

### 4.3 历史查询页

- 条件：时间范围（起/止、"今天/近 7 天"快捷键）、条码（部分匹配）、相机、无码状态、下发状态、有无图片
- 结果表：时间 / 条码 / 相机 / 无码 / 重量 / 尺寸 / **缩略图**（点击看原图）/ 下发状态 / 追踪号
- **导出 CSV**：按当前筛选条件**全量**导出（UTF-8 BOM，Excel 双击不乱码），字段含追踪号、全部条码、无码标记、图片路径、下发状态与时间

### 4.4 统计页（看板）

- 五个 KPI：总包数 / 读码率 / 无码率 / 无码数 / 有图·下发成功
- 四个维度：**按相机**（谁在干活）、**按班次**（哪个班干得多）、按小时、按日期
- 支持按相机过滤、导出统计 CSV、下方改班次设置

### 4.5 诊断页（现场排查首选）

| 来源 | 内容 |
|---|---|
| 采集宿主日志 | 上电、触发、出码、错误 |
| 平台日志 | 合并/去重/下游/监控 |
| **SDK 日志** | 大华 SDK 自己的日志（排相机侧问题） |
| 事件缓冲 spool | 采集宿主写给平台的事件 |
| 相机状态事件 / 登录审计 | 掉线与告警记录、登录与改密记录 |

用法：选时间范围 → 点某个来源卡片 → 列文件 → **查看**（尾部 200 行）或 **下载**；
要回传给我们分析就点 **一键打包下载 zip**（带 README 说明，标准 zip，离线可解）。

### 4.6 配置页 → 账号与安全

| 操作 | 说明 |
|---|---|
| 修改我的密码 | 至少 8 位且含字母数字；改完其它设备的会话会失效 |
| 新增账号 | 角色：`admin`（全部）/ `operator`（能改配置）/ `viewer`（只读） |
| 禁用 / 重置密码 / 删除 | 管理员操作；删改最后一个管理员会被拒绝 |
| 登录限制 | 密码错误次数上限、锁定时长、会话时长 |
| 服务令牌 | `X-Api-Key`，给脚本/上位机集成用；可一键轮换（旧的立刻失效） |

> 管理接口未登录一律 401；密码连续错 5 次锁 15 分钟（默认）。忘记密码时用服务令牌调
> `POST /api/auth/users/reset-password`（或让另一个管理员在界面上重置）。

## 5. 常用现场动作（照着敲）

以下命令都在交付包根目录（`run.ps1` 所在目录）执行。

### 5.1 软触发一次 / 人工补码

```powershell
# 看当前 provider 与触发模式（不会启动 SDK，秒回）
powershell -ExecutionPolicy Bypass -File .\tools\host-command.ps1 -Status

# 软触发一次（要求 triggerMode=2）
powershell -ExecutionPolicy Bypass -File .\tools\host-command.ps1 -SoftTrigger

# 触发模式不是软触发时，排查用（跳过校验）
powershell -ExecutionPolicy Bypass -File .\tools\host-command.ps1 -SoftTrigger -Force

# 人工补码
powershell -ExecutionPolicy Bypass -File .\tools\host-command.ps1 -Recode -Code SF1234567890
```

**这两种情况走的路径不同，脚本会自己挑（看输出第一行）：**

| 现场情况 | 走哪条路 | 输出特征 |
|---|---|---|
| **采集宿主正在跑**（正常生产状态） | 走宿主的**常驻命令通道**（本机命名管道）——不用停宿主、也不跟它抢相机 | `[命令通道] 宿主在跑 → 走常驻通道` |
| 宿主没在跑 | 退回"新起一个宿主进程执行命令"的老办法（会自己开一次 SDK，所以必须宿主没在跑，否则报 3001 相机被占用） | `[命令通道] 连不上（采集宿主没在跑）→ 退回…` |

平台界面**实时监控页**右上角也有 **「软触发一次」** 按钮，点一下就是同一条常驻通道，结果直接显示在按钮下面。

通道名由 runtime 目录算出来（`dws-edge-host-<路径哈希前 8 位>`），所以同一台机器上开多套 runtime 也不会互相串。

退出码（脚本会翻译成人话）：

| 退出码 | 含义 | 怎么办 |
|---|---|---|
| 0 | 成功 | — |
| 1 | 参数错误 | 按提示补参数 |
| 2 | 采集宿主启动失败 | 查加密狗 / 相机 / 网段 |
| 4 | 命令执行失败 | 看 `logs\host-*.log` 里 `[cmd]` 那几行 |
| 5 | **触发模式不允许** | `set-trigger-mode.ps1 -Mode soft` 后重启宿主 |
| 6 | provider 不支持 | 换 provider 或改用别的命令 |

> 触发前记得镜头视野里放一张有条码的面单：软触发只是"让相机拍一张"，解码结果由相机给。

### 5.2 改触发模式

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\set-trigger-mode.ps1 -Mode hard   # 硬触发（光电）
powershell -ExecutionPolicy Bypass -File .\tools\set-trigger-mode.ps1 -Mode soft   # 软触发
powershell -ExecutionPolicy Bypass -File .\tools\set-trigger-mode.ps1 -Mode free   # 自由拉流（狂扫）
```

改完**重启采集宿主**才生效。

### 5.3 批量改相机清单（17 台）

```powershell
# 1) 编辑清单文件（每行一台：ip=... ,pos=top）
notepad .\config\cameras-17.example.txt

# 2) 一键应用（写 cfg → 启动校验 → 失败自动回滚）
powershell -ExecutionPolicy Bypass -File .\tools\apply-config.ps1 -CameraList .\config\cameras-17.example.txt
```

只想看会改成什么、不落盘：加 `-Preview` 到 `make-camera-cfg.ps1`：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\make-camera-cfg.ps1 -CameraList .\config\cameras-17.example.txt -Preview
```

### 5.4 一键自检（交付前必跑）

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\self-check.ps1
```

加 `-SkipTrigger` 则不动采集侧（只看环境与平台）。

### 5.5 回滚配置

- 界面：配置页 → 配置备份与回滚 → 选一份 → 回滚
- 命令行：把 `config\`（或 `Cfg\`）下对应的 `*.bak-<时间戳>` 改名回原名即可
- 采集侧最稳的是：`apply-config.ps1` 校验失败时**自动回滚**（会用 `LogisticsBase.cfg.rollback-*` 那个回滚点）

### 5.6 什么时候必须重启采集宿主

| 改动 | 是否要重启宿主 |
|---|---|
| 相机清单、触发模式、存图策略 | **要** |
| `gateway.ini` 里任何配置 | **要** |
| 平台侧：下游参数、条码规则、监控阈值、班次 | 不要（保存即生效/热加载） |
| 平台本身：`platform\appsettings.json`（如轮询间隔、端口） | 重启**平台**，与宿主无关 |

### 5.7 采集宿主与平台的启停

```powershell
.\run.ps1                     # 采集宿主（前台，Ctrl+C 停）
.\run.ps1 -Platform           # 平台（前台，Ctrl+C 停）
.\run.ps1 -Both -TriggerOnce  # 两个一起（平台后台），并触发一次

# 不想看到两个黑窗口（推荐现场这样跑）
.\run.ps1 -Background                       # 隐藏启动两个进程，立即返回
powershell -ExecutionPolicy Bypass -File .\runtime\tools\stop-all.ps1 -Status   # 看进程状态
powershell -ExecutionPolicy Bypass -File .\runtime\tools\stop-all.ps1          # 停止

# 仅用于确认进程状态：
Get-Process DwsEdge.Host, DwsEdge.Platform -ErrorAction SilentlyContinue
```

**关于那两个黑窗口（现场最常问）**：

* 黑窗口**就是进程本身**——点右上角 × 或按 Ctrl+C 等于停掉采集/平台，**不能关**；
* 想让它一直在又不想看窗口，三种做法：
  1. **最小化**（最省事，进程继续跑）；
  2. **隐藏启动**：`.\run.ps1 -Background` 或 `runtime\tools\start-all.ps1`（窗口不出现，日志写到 `logs\host-console-*.log` 与 `logs\platform-console-*.log`）；
  3. **开机自启**（`install-autostart.ps1`）默认就是隐藏启动的，装了之后开机不会弹窗。
* 隐藏启动后要看状态/停服务，就用 `runtime\tools\stop-all.ps1`（`-Status` 只看不停）。
* 想让窗口彻底消失、进程随机器自动恢复，那是**服务化**（见第 8 章），需要先在真机验证 SDK 在服务账户下的表现。

> 当前版本没有服务化，重启机器后要人工拉起。**无人值守场景**请见第 8 章的交付建议。

## 6. 故障处理速查

### 6.1 采集侧

| 现象 | 检查 | 处理 |
|---|---|---|
| 宿主启动报 2200 | 加密狗 | 插好加密狗（必须插在盒子本机）、装驱动；换 USB 口重试 |
| 宿主启动报 3000 | 相机数与 cfg 不符 | 核对 `Cfg\LogisticsBase.cfg` 的 `num` 与 `enable="1"` 的台数；确认相机在线 |
| 宿主启动报 3001 | 相机被占用 | 关掉 MVViewer / EasyID 等工具 |
| 报 1000 / 1001 | cfg 路径或编码 | cfg 缺失或不是 GB2312；从 SDK 目录拷一份 |
| 相机"未发现" | 网线/网段/供电 | 单独 ping 该相机；确认与盒子同网段；设备信息页有"未发现"标记 |
| 设备信息页同一台相机显示两条（一条在线"未在清单中"、一条离线） | 清单按 IP 写、SDK 只报"厂商:序列号" | 正常应已自动关联：看 `config\camera-identity.ini` 里有没有该相机的 `ip=key`，宿主日志有没有"相机身份关联"那行。都没有就让这台相机先过一次包裹（回调会带 IP）或重启一次宿主（会读 SDK 日志重建） |
| 软触发返回 5 | 触发模式 | `set-trigger-mode.ps1 -Mode soft` 并重启宿主 |
| 软触发/补码说"命令通道连不上" | 采集宿主没在跑 | 先 `run.ps1` / `runtime\tools\start-all.ps1` 把宿主起来；起来后再点界面「软触发一次」或跑 `host-command.ps1`（脚本会自动退回新起进程的老办法，但那种方式要求宿主没在跑） |
| 软触发返回 0 但没出码 | 光电/对焦/曝光 | 看 SDK 日志；确认镜头对焦、光源；硬触发模式下软触发不会出码 |
| 宿主自己一直在出包 | 是否开了定时触发 | 启动参数里有没有 `--trigger-interval`；确认 `gateway.ini` 的 `[test]` 段是关的 |

### 6.2 平台侧

| 现象 | 检查 | 处理 |
|---|---|---|
| 浏览器打不开 | 平台没起 / 端口 / 防火墙 | `Get-Process DwsEdge.Platform`；`netstat -ano \| findstr 8090`；放行 8090 入站 |
| 本机能开、其它电脑打不开 | 用错 IP / 防火墙 | 其它电脑要用**盒子的局域网 IP**（不能填 `localhost`，那会访问它自己）；确认 `netstat` 里是 `0.0.0.0:8090`；放行 8090 入站 |
| 两个黑窗口能不能关掉 | 窗口就是进程 | **不能关**（关了等于停采集/停平台）：最小化，或用 `.\run.ps1 -Background`（等价 `runtime\tools\start-all.ps1`）隐藏启动；停止/看状态用 `runtime\tools\stop-all.ps1` |
| 隐藏启动后怎么看日志 | 日志重定向到文件 | 看 `runtime\logs\host-console-*.log` 与 `runtime\logs\platform-console-*.log`，或在平台"诊断"页看 |
| 页面能开但没数据 | spool 没事件 / 消费位点 | 看诊断页"事件缓冲"；确认采集宿主在写 `spool\events-*.jsonl` |
| 图片不显示（"无图"） | 该包裹确实没落图 | 诊断页看平台日志；确认存图策略与图片目录可写 |
| 历史查不到今天的包裹 | 时间范围 | 默认范围是"昨天~今天"；或看诊断页确认事件是否入库 |
| 导出 CSV 字段对不上 | 筛选条件 | 导出用当前筛选条件**全量**导出，不受分页影响 |
| 下游收不到数据 | 连接 / 端口 / 模板 | 配置页 → 下游输出 → **测试连接** + 看"最近下发记录"；确认模板带 `\r\n` |
| 告警刷屏 | 阈值太紧 | 配置页把"离线告警秒数"调大（如 20-30 秒） |
| 登录被锁 | 密码错太多 | 等锁定时间（默认 15 分钟）；或让管理员重置密码 |
| 忘记管理员密码 | — | 用服务令牌（`config\auth.json` 的 `serviceKey`）调 `POST /api/auth/users/reset-password` |

### 6.3 磁盘与性能

| 现象 | 检查 | 处理 |
|---|---|---|
| 磁盘越来越满 | 统计页/诊断页看占用 | 调小"图片保存天数"、把"磁盘水位"设到 80-85、把图片目录指到数据盘 |
| 界面刷新慢 | 平台轮询间隔 | 见附录 A；`Spool:PollIntervalMs` 默认 100ms（延迟 130ms 左右），机器吃力可调回 500 |
| 图片加载慢 | 图片盘是机械盘/网络盘 | 图片目录放**本地 SSD/NVMe**；缩略图已由平台缓存 |

## 8. 无人值守与真机验收（重要）

### 8.1 开机自启（当前版本的做法）

当前版本是控制台进程，可以选择：

1. **计划任务**（临时方案）：创建两个"开机启动"任务，分别执行
   `powershell -ExecutionPolicy Bypass -File D:\dws\run.ps1`（采集宿主）与 `... run.ps1 -Platform`。
   勾选"不管用户是否登录都运行"，并设置失败后重启（每 1 分钟，最多 3 次）。
2. **服务化**（建议，下一步计划）：把宿主与平台做成 Windows 服务，带崩溃自动重启与看门狗。
   注意：大华 SDK 在"服务账户、无桌面会话"下的表现需要在**真机上先验一次**。

### 8.2 真机验收项（软件之外、必须现场测）

| 项 | 怎么测 | 通过标准 |
|---|---|---|
| 多相机接入 | 17 台全部上电启动 | 全部识别并在线，连续运行 4 小时不掉线 |

## 附录 E：版本号口径与交付包核验

### E.1 版本号只有一个来源

开发仓库根目录的 `VERSION` 文件是**唯一来源**，内容形如 `V1.0.3`。改版本只改这一个文件。

| 位置 | 怎么来的 | 长什么样 |
|---|---|---|
| 仓库 `VERSION` | 手工维护（唯一来源） | `V1.0.3` |
| exe / dll 的文件属性（程序集版本） | `build.ps1` 编译时从 `VERSION` 注入 | `1.0.3` |
| 交付包目录名 | `make-package.ps1` 从 `VERSION` 取 | `DWS-Edge-Min_V1.0.3_20260918` |
| 包内 `VERSION.txt` → 版本号 | 同上 | `V1.0.3` |
| 包内 `VERSION.txt` → 程序集版本 | 打包时从**包里刚拷进去的 exe** 现读 | `1.0.3` |
| 包内 `VERSION.txt` → 源码提交 | 打包时从 git 取 | `caf7a52` |

要点：**程序集版本 = 版本号去掉前面的 `V`**。比如包是 `V1.0.3`，则 `DwsEdge.Host.exe` 的属性里必须显示 `1.0.3`。
程序集版本里还带一串源码提交号（如 `1.0.3+caf7a52`），用于对回是哪次提交构建的。

### E.2 交付前怎么核验（推荐一条命令）

在交付包目录里直接跑（不用带参数，它会自己找桌面上最新的包）：

```powershell
powershell -ExecutionPolicy Bypass -File .\runtime\tools\check-package.ps1
```

它检查五件事，最后给一句"能不能交付"：

1. 包名里的版本号 = `VERSION.txt` 里的版本号；
2. `VERSION.txt` 的版本号 = exe/dll 的文件属性（程序集版本）；
3. `checksums.txt` 里每个文件的 SHA256 都对得上（包没被改动或损坏）；
4. 包内产物与开发仓库 `runtime` 逐文件一致（只允许 3 处设计内的差异，见下）；
5. 可选：在临时目录里跑一遍 `self-check.ps1`，看服务能不能起来。

常用变体：

```powershell
# 只核对版本与校验和（不碰仓库、不启进程，最快）
powershell -ExecutionPolicy Bypass -File .\runtime\tools\check-package.ps1 -SkipRepoCompare

# 连启动自检一起跑（会拷贝一份 runtime 到临时目录，不污染本包）
powershell -ExecutionPolicy Bypass -File .\runtime\tools\check-package.ps1 -RunSelfCheck
```

退出码：`0` = 全部通过可交付；`1` = 有失败项，别发。

### E.3 允许的差异（不算问题）

打包时按设计会改三处，核验脚本会把它们单列成"设计内的差异"：

| 文件 | 打包时改成什么 | 为什么 |
|---|---|---|
| `runtime\Cfg\LogisticsBase.cfg` | 相机清单示例化成 1 台 `ip=172.20.10.11` | 不泄露上一台设备的相机 IP / 序列号 |
| `runtime\config\gateway.ini` | provider 改成 `dahua-dws` | 出厂按真机交付 |
| `runtime\platform\appsettings.json` | 只在内容真变时才改，且保留原 BOM | 保证和源码产物逐字节一致 |

另外运行期目录（`spool` / `data` / `logs` / `images` / `cache`）在出厂包里是**空的**：现场首次启动会自动生成账号与随机初始密码。

### E.4 没接相机时自检"报红"是正常的

真机包在**没有相机 / 没有加密狗**的机器上跑 `self-check.ps1`，会只剩一条失败：

| SDK 返回码 | 含义 | 现场怎么办 |
|---|---|---|
| `2200` | 没插加密狗 | 把随相机的加密狗插到上位机 USB 上 |
| `3000` | 相机数与配置不符 / 没相机连上 | 确认相机 IP 与 `Cfg\LogisticsBase.cfg` 里 `enable="1"` 的相机一致 |
| `3001` | 相机被占用 | 关掉大华 Demo 等占用相机的程序再试 |

这种情况下软触发与人工补码会自动降级成"跳过"，属于**预期的降级**，不是包的问题；
`check-package.ps1 -RunSelfCheck` 会把这种结果判为通过并注明原因。接上真机再跑一次就是全绿。
